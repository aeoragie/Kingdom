# 🛠️ 6. 개발과 기술

> 이 페이지: 기술 원칙, Phase별 개발 계획, 리스크, 착수 준비, 그리고 개발하면서 조준할 밸런스 수치 목록.

# 기술 원칙

> 전제: **순수 C++ 시뮬레이션 코어 + UE5 뷰 레이어.** UE는 그리고 입력받는 역할만 한다. 이 분리를 끝까지 지키는 것이 계획 전체의 척추.

## 온라인 전환 대비

싱글 → 온라인의 진짜 걸림돌은 시간 모델이 아니라 **권위 구조**다.

> **UE 코드가 코어 상태를 직접 수정하지 않는다.** 모든 변경은 커맨드를 코어에 제출 → 코어가 검증·적용 → UE는 결과를 읽기만.

싱글에선 불필요한 우회로 보이지만, 이 규칙 하나가 온라인 전환 가능성의 전부다.

## 결정론

- 게임 시간은 **정수 틱**. 부동소수점 누적 금지
- 능력치 계산도 정수 또는 고정소수점
- 배속은 틱 간격이 아니라 **틱 소비 속도**로 구현
- 확률 판정(모사 등)은 시드 기반 PRNG를 코어 상태에 두고 커맨드 로그에 포함
- 커맨드 로그 = 세이브 = 리플레이 = 버그 재현 = (나중에) 서버 검증

## 틱 간격은 설정값

코어는 "틱 N번 진행"만 안다. 몇 초에 한 번인지는 바깥에서 정한다.

- 싱글: 빠르게 (0.5초 등)
- 온라인(장래): 30초

싱글에서 30초 틱이면 플레이어가 5분씩 기다리게 되고 결국 최고 배속으로만 돌리게 된다. 설정값으로 빼두면 지금 정할 필요가 없고 전환 때도 안 흔들린다.

## 능력치 레이어

```
최종값 = (기본 + 성장누적) × 특기배율 + 장비합 + 상황보정
```

레이어를 분리 보관해야 UI에서 "무력 72 (기본 58 +성장 6 +장비 8)"를 보여줄 수 있고, 장비를 벗겼을 때 정확히 되돌아간다. 합쳐서 하나로 저장하면 반드시 후회한다. 더티 플래그 + 캐시로 구현.

## 맵 데이터

맵 폭·높이를 상수로 박지 말고 **초기화 파라미터**로 받는다. 헥스 배열도 고정 크기가 아닌 런타임 할당. 그래야 나중에 숫자만 바꿔 100판 돌려보고 고를 수 있다.

# 개발 계획

**Phase 0~3.5가 수직 슬라이스다.** 1막의 핵심 루프(거점 공략 → 영역 확장 → 건설 → 임명)가 돌아가는 상태가 1차 목표.

> **순서 원칙**: 지형·연결거점은 보급선의 일부이므로 Phase 1에, 임명은 지속 소모라 틱 루프의 일부이므로 Phase 3에. 정찰·시야는 AI 판단 범위를 바꾸므로 전투와 분리해 독립 Phase로 둔다.

## Phase 0 — 골격 (1~2주)

- UE5 프로젝트 + `Source/KingdomCore/` (UE 헤더 0개인 순수 C++ 정적 라이브러리) + `Source/KingdomGame/`
- KingdomCore만 CMake로도 빌드되게 별도 설정 (초 단위 이터레이션용)
- 유닛 테스트 프레임워크 연결

**게이트**: UE 안에서 코어 함수 호출값이 화면에 찍히고, UE 없이 콘솔에서 테스트가 돈다.

⚠️ 코어에 `CoreMinimal.h`가 한 줄이라도 들어가는 순간 분리는 끝난 것.

## Phase 1 — 헥스 코어 (3~4주, UE 안 켬)

- 축좌표계, 이웃 순회, 거리, A* 경로탐색
- **지형 데이터** — 이동 비용과 방어 보너스를 같은 테이블에서 읽는다
- **지배영역 전파**
- **보급선 판정** + 건물 가동/차단
- **연결 거점** — 보급선의 물리적 실체. 처음부터 포함할 것, 나중에 얹을 기능이 아니다
- 포위·차단 검사
- ASCII 덤프로 콘솔 출력

**게이트**: 콘솔에서 부대를 움직이면 영역이 번지고, 거점을 끊으면 외곽 생산이 멈춘다.

여기가 게임의 정체성. 재미가 여기서 안 나오면 그래픽을 붙여도 안 나온다.

## Phase 2 — 첫 픽셀 (1~2주)

액터를 헥스마다 스폰하면 프로젝트가 끝난다. 대신:

- 지형은 평면 메시 + 하이트맵. 지형 타입은 게임 중 안 변하므로 **정적 텍스처에 구워둔다**
- 소유권 배열을 축좌표 공간 `UTexture2D`(R8)에 업로드
- 머티리얼: 월드좌표 → 축좌표 → 텍셀 샘플 → 팔레트 룩업
- 경계선은 이웃 텍셀 비교로 생성
- `BuildingID` 채널 추가 (RG8 한 장 또는 R8 두 장)
- 카메라 팬/줌, 마우스 헥스 피킹

수만 헥스가 드로우콜 하나, 갱신은 텍스처 업로드 한 번.

**게이트**: 세력 색이 칠해지고 마우스 헥스가 하이라이트되며 60fps.

## Phase 3 — 코어 루프 (3~4주)

- **고정 틱 시뮬레이션 루프**
- 커맨드 패턴 — `MoveArmy` / `Build` / `Appoint` / `EquipItem` / `Recruit`
- 행동력 회복·소모·대기열
- **임명 시스템** — 지속 소모가 틱 루프의 일부이므로 여기서 함께
- 세이브/로드 = 시드 + 커맨드 로그
- 배속, 일시정지

**게이트**: 배속으로 100틱을 논스톱 진행. 세이브 후 로드하면 완전히 같은 상태.

## Phase 3.5 — 원시 AI

AI를 후반부로 미루면 안 된다. 9개 세력이 전부 AI이므로 **AI가 재미없으면 게임 전체가 재미없다.**

- 가까운 거점 공략, 자원 나면 건설, 영웅 나면 임명 수준의 원시 AI
- 세력끼리 돌아가는 상태 확보

## Phase 4 — 헤드리스 시뮬레이터 (1~2주)

**보조 도구가 아니라 필수 인프라.** 밸런스 수치의 거의 전부가 이 도구로만 답을 낼 수 있다.

- UE 없이 실행되는 CLI 바이너리
- AI vs AI, N판 배치 실행
- CSV 출력: 국가별 승률, 평균 소요 시간, 성장 곡선, 임명 소모 대비 가용 행동력, 격차 승리 발동 시점, 세력 간 최초 접촉 시점
- 맵 크기를 여러 값으로 돌려 비교

**게이트**: `./sim --games 1000 --seed 42 > out.csv`

성장 + 장비 + 건설 + 영역 + 임명이 곱해지면 파워 커브를 손으로 못 잡는다.

## Phase 5 — 데이터 파이프라인 (1~2주)

- 엑셀 → CSV → DataTable → 코어 구조체
- 영웅 / 장비 / 성장곡선 / 지형 / 이름 음절 테이블
- 초상화는 `TSoftObjectPtr` (하드 레퍼런스로 걸면 영웅 하나 로드에 전체가 메모리에 올라옴)

## Phase 6 — 영웅 심화 (3~4주)

스탯과 장비가 행동력 효율에 직결되므로 전투보다 먼저 넣는다.

- 스탯 4종 — 커맨드별 소모 감소(하한 있음)
- 장비 5슬롯, 강화(6강 안전 → 확률 → 실패 시 하락)
- 충성도 — 이탈과 업무 효율
- 패시브·액티브 스킬

**게이트**: 같은 행동력으로 고스탯 영웅이 더 많이 움직이고, 충성도가 낮은 영웅의 생산이 줄어든다.

## Phase 7 — 전투와 병종 (4~5주)

- 전투 판정, 사기
- 병종 4종 + 지형 상성
- 부대 편성 — 총대장 통솔로 규모 결정, 부장 일부 반영
- **운반병과 적지 보급** — 야전 건설(목책·요새·야전 창고)
- AI에 지형 판단과 보급 계산 추가

⚠️ 원정 나갔다가 굶어 죽는 AI가 나오면 게임이 우스워진다. AI 판단 항목 중 가장 어려운 축이라 여유를 두었다.

## Phase 8 — 정보전 (2~3주)

정찰·시야를 독립 Phase로 분리한 이유: **AI 9개가 전부 자기 시야 안에서만 판단하도록 고쳐야 하므로** 기존 AI 로직을 전반적으로 손본다.

- 세력별 시야 계산 (정찰병 반경 + 감시탑)
- 수집 정보: 병력 규모, 영웅, 병과, 보급고
- 정찰병끼리만 교전
- 시야 텍스처 렌더링 (소유권과 같은 방식, 단 갱신이 잦다)

**게이트**: AI가 모르는 적을 못 치고, 플레이어도 정찰 없이는 적 보급선을 못 찾는다.

## Phase 9 — 외교와 모사 (3~4주)

- 관계 상태(평시 / 우호·동맹 / 전시·험악)와 상태별 가능 행동
- 우호 증진(횟수 제한, 정치력 차등), 정전 요청
- 모사 판정 (시드 PRNG를 코어에)
- 동맹 공략 요청 — AI 수락 판단, 보상 배분
- 고대 몬스터 거점, 거대 세력 대항 연합 이벤트
- 승리·패배 처리 (국력 공식, AI 승리 3단계)

## Phase 10 — UI (6~10주)

이 장르의 본체이며 가장 오래 걸린다.

- `ListView` / `TileView` 가상화, `UUserWidget` 풀링
- **알림 시스템과 이벤트 로그** — 실시간이므로 필수
- **세션 재개 요약 화면** — 하루 2시간씩 끊어 하는 60시간짜리므로
- 커맨드 대기열 취소·재배열, 임명 화면, 영웅 목록 정렬·필터
- 국력 순위표 (승리 조건과 같은 값)

## Phase 11 — 콘텐츠 (계속)

영웅 데이터, AI 초상화, 이벤트. 코드보다 오래 걸린다.

# 리스크

- **AI가 최대 난제.** 9개 세력이 전부 AI다. 헥스 방어선 이해, 외교 판단, 동맹 공략 참여 판단이 특히 어렵다. 유틸리티 기반 의사결정이 무난하지만 어느 방식이든 손이 많이 간다.
- **밸런싱이 손으로 안 잡힌다.** 비대칭 국가 × 성장 × 장비 × 건설 × 영역 × 임명. Phase 4 시뮬레이터 없이는 방법이 없다.
- **UI가 몸통이다.** 클라 경험이 없으므로 Phase 2와 10에서 예상보다 오래 걸린다고 미리 잡아둘 것. 실시간이라 알림·이벤트 로그·세션 재개 요약까지 필요해 부담이 더 크다.
- **초상화 공유는 도박.** 등급별 정책(일반=아키타입 공유 / 네임드=별도 제작)으로 완화되지만, 일반 영웅의 시각 언어가 능력치와 일치하는지가 관건. 아트 문제가 아니라 UI 설계 문제로 다뤄야 한다.
- **UE C++ 함정.** `UPROPERTY()` 없는 raw `UObject*`는 GC가 조용히 날린다. 컴파일도 되고 대부분 돌아가다가 특정 타이밍에만 죽는다. `UObject`와 `TSharedPtr`는 다른 세계이므로 섞지 말 것. 코어가 분리돼 있으면 이 경계가 자연스럽게 지켜진다.

# 착수 준비

상세 설정은 달라질 수 있으므로 **반드시 거쳐야 하는 것만** 적는다.

## 환경

- **엔진** — Epic Games Launcher로 UE5 최신 안정 버전. 소스 빌드 불필요. Visual Studio 2022는 "C++를 사용한 게임 개발" 워크로드 필수
- **저장소** — Git + **Git LFS**. `.uasset`·`.umap` 바이너리가 많아 LFS 없이 시작하면 나중에 되돌리기 어렵다. `Binaries/`·`Intermediate/`·`Saved/`·`DerivedDataCache/`는 제외
- **KingdomCore 독립 빌드** — UE 없이 CMake로 빌드되고 테스트가 도는 상태를 **첫 주에** 만든다. 나중에 붙이면 이미 UE 의존성이 섞여 있다

## Claude 활용

- **Claude Code** — 터미널에서 코드베이스를 직접 읽고 수정한다. KingdomCore는 순수 C++에 테스트가 있어 작성 → 컴파일 → 테스트까지 한 번에 돌린다
- **기획서를 리포지토리에 둘 것** (`docs/`) — 매번 맥락을 다시 설명할 필요가 없어진다
- **작업 분담** — KingdomCore는 AI 협업이 잘 듣는다(표준 C++, 검증 가능). UE 쪽(머티리얼·UMG·에디터 작업)은 범위가 좁고 API 시그니처가 버전마다 달라지므로 **컴파일로 검증**해야 한다

## 에셋 — 지금 사지 않는다

Phase 2까지는 평면 메시와 색상 머티리얼이면 충분하다. 프로토타입 단계에 산 에셋은 대부분 안 쓴다.

Phase 11(콘텐츠) 시점에 필요해지면 — 지형·환경은 Fab의 스타일라이즈드 팩, UI는 CC0 소스나 직접 제작, 영웅 초상화는 AI 생성.

⚠️ 초상화는 **스타일 고정이 전부**다. 프롬프트 템플릿과 파라미터를 먼저 확정하고 배치로 뽑아야 화풍이 안 흔들린다.

# 미결 — 밸런스 수치 (Phase 4에서 조준)

> 시스템 설계(구조)는 확정되어 각 페이지 본문으로 옮겼다. 남은 것은 전부 개발하면서 맞추는 숫자다. 착수를 막는 미결은 없다.

| 항목 | 내용 |
|---|---|
| 맵 스케일 | 총 헥스 수. 여러 값으로 돌려 평균 소요 시간과 세력 간 최초 접촉 시점을 뽑는다. ⚠️ 맵을 키워서 60시간을 채우려 하지 말 것 — 이동 시간만 늘어 후반이 늘어진다 |
| 종족 할인율 | 유지비·고용 비용을 몇 % 깎을지. 종족 일치율 대비 승률로 조준. 너무 크면 타종족 고용이 죽고, 작으면 종족 축이 무의미해진다 |
| 임명 소모율 | 시설 종류별로 다르게 — 농장은 적게, 대도시 성주는 많게. 그러면 어느 영웅을 어디에 앉힐지가 능력치뿐 아니라 회복 속도로도 갈린다 |
| 슬롯별 소모 감소 곡선 | 감소폭이 크면 고레벨 내정 영웅 한 명이 모든 걸 해결하고, 작으면 성장 이점이 반감된다 |
