# 모듈과 폴더 구조 - Public, Private, include 경로

> 언리얼 코드는 모듈 단위로 빌드된다.<br>모듈 폴더 안의 Public / Private 규칙과 include 경로가 어떻게 잡히는지 정리한다.

---

# 모듈 폴더의 기본 모양

```
Source/
  KingdomCore/                    모듈 하나 (이름 = 폴더 이름)
    KingdomCore.Build.cs          모듈 정의(의존 모듈, 빌드 옵션)
    Public/                       밖에 공개하는 헤더
      KingdomCore/                include 경로의 이름표 (아래 설명)
        Simulation.h
    Private/                      구현(.cpp)과 내부 전용 헤더
      Simulation.cpp
  KingdomGame/
    KingdomGame.Build.cs
    Public/
      KingdomGameInstance.h
    Private/
      KingdomGameInstance.cpp
```

- 모듈 하나는 에디터 빌드에서 DLL 하나가 된다(`UnrealEditor-KingdomCore.dll`).
- 서버 라이브러리로 치면 `include/`와 `src/`를 나누는 것과 같다.

---

# Public과 Private

| 폴더 | 들어가는 것 | 누가 볼 수 있나 |
|---|---|---|
| `Public/` | 다른 모듈이 쓸 헤더(공개 API) | 이 모듈에 의존하는 모든 모듈 |
| `Private/` | `.cpp` 구현, 이 모듈 안에서만 쓰는 헤더 | 이 모듈 자신만 |

**UBT가 include 경로를 자동으로 잡는다**
- `KingdomGame.Build.cs`에 KingdomCore 의존을 적으면, UBT가 `KingdomCore/Public/`을 KingdomGame의 include 경로에 넣는다.
- `KingdomCore/Private/`는 넣지 않는다.<br>그래서 다른 모듈이 내부 구현 헤더를 include하면 컴파일이 안 된다.<br>공개 API만 쓰도록 빌드 시스템이 막아 준다.

**의존을 적는 두 가지 방법 (`Build.cs`)**
```csharp
PublicDependencyModuleNames.AddRange(new string[] { "Core", "CoreUObject", "Engine" });
PrivateDependencyModuleNames.AddRange(new string[] { "KingdomCore" });
```
- **Public 의존**: 내 Public 헤더가 그 모듈의 헤더를 include할 때.<br>나를 쓰는 모듈에도 그 의존이 전해진다
- **Private 의존**: 내 .cpp에서만 쓸 때.<br>나를 쓰는 모듈에는 전해지지 않는다
- 기본은 Private로 두고, 공개 헤더에서 꼭 필요할 때만 Public으로 올린다.<br>서버의 CMake `target_link_libraries(... PUBLIC / PRIVATE ...)`와 같은 개념이다

# include 경로에 이름표 붙이기 (`Public/KingdomCore/`)

```cpp
#include "KingdomCore/Simulation.h"   // 지금 구조
#include "Simulation.h"               // 이름표 폴더가 없었다면
```

- 에디터 빌드에서는 엔진 모듈 수백 개의 `Public/`이 include 경로에 들어간다.<br>`Version.h`, `Command.h` 같은 흔한 이름은 엔진·플러그인 헤더와 겹칠 수 있다
- 폴더 이름을 앞에 붙이면 "우리 코어의 그 파일"로 확정된다.<br>네임스페이스를 파일 경로에 적용한 것과 같다
- 엔진도 같은 방식이다: `#include "Engine/World.h"`, `#include "GameFramework/Actor.h"`
- KingdomCore의 CMake 빌드도 같은 `Public/`을 include 경로로 써서, 두 빌드의 include 문장이 똑같다

**KingdomGame은 이름표 폴더가 없다**
- 게임 모듈은 보통 클래스 이름이 곧 파일 이름이고, 프로젝트 접두어가 붙는다(`KingdomGameInstance.h`).<br>이름 자체가 고유해서 충돌하지 않는다
- 코어는 `Simulation.h`처럼 일반적인 이름을 쓰므로 폴더로 구분했다

# 소스 파일을 추가했을 때

- UBT는 모듈 폴더 아래의 `.cpp`를 **자동으로 전부** 빌드에 넣는다. 파일 목록을 따로 적지 않는다.<br>(그래서 테스트 코드는 모듈 밖 `Source/KingdomCoreTests/`에 둔다. 안에 두면 UBT가 같이 빌드해 버린다)
- 하지만 VS 솔루션 파일(`.sln`/`.slnx`)은 생성할 때의 파일 목록을 담고 있다.<br>새 파일이 VS 솔루션 탐색기에 보이게 하려면 **`.uproject` 우클릭 → Generate Visual Studio project files**를 다시 한다
- 빌드는 VS 프로젝트 파일과 상관없이 UBT가 폴더를 보고 하므로, 다시 생성하지 않아도 빌드 자체는 된다.<br>VS 화면에만 안 보일 뿐이다
- KingdomCore의 CMake 빌드는 반대로 `CMakeLists.txt`에 파일 목록을 직접 적어야 한다
