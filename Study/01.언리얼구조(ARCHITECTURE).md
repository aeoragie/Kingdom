# 언리얼 구조 - 핵심 객체와 돌아가는 방식

> 서버 개발자가 언리얼을 러프하게 파악하기 위한 지도.<br>깊게 팔 곳은 끝의 "더 볼 것"에 모아 둔다.<br>기준: UE 5.8.

---

# 1. 한눈에 보기

```
프로세스
└─ UEngine (UGameEngine / 에디터에서는 UEditorEngine)      엔진 본체. 메인 루프를 돈다
   └─ UGameInstance                                        게임 하나에 하나. 맵이 바뀌어도 산다
      ├─ Subsystem들 (UGameInstanceSubsystem)              전역 서비스
      └─ UWorld                                            지금 열려 있는 "세계" 하나
         ├─ ULevel (Persistent Level + 스트리밍 레벨)      맵 데이터 묶음
         │  └─ AActor들                                    세계에 놓인 모든 것
         │     └─ UActorComponent들                         액터의 기능 조각
         ├─ AGameModeBase                                  규칙 (서버에만 있음)
         ├─ AGameStateBase                                 모두가 보는 공유 상태
         └─ APlayerController → APawn                       플레이어의 입력 → 조종하는 몸
```

**서버 개발 비유**
- **UEngine**: 서버 프로세스의 메인 루프와 런타임
- **UGameInstance**: 애플리케이션 전역 객체. 프로세스가 켜져서 꺼질 때까지 하나만 있다
- **UWorld**: 방(룸) 하나, 또는 존 하나의 시뮬레이션 공간
- **AActor**: 그 공간 안의 엔티티
- **UActorComponent**: ECS의 컴포넌트에 가까운 기능 조각. 다만 데이터와 로직을 함께 가진다

# 2. 모든 것의 바탕 - UObject

언리얼이 관리하는 객체의 공통 부모.<br>`U`로 시작하는 클래스가 이것이다(`AActor`도 UObject를 상속한다).

**UObject가 주는 것**
- **GC (가비지 컬렉션)**<br>언리얼이 주기적으로 도달 가능성을 검사해서, 아무도 참조하지 않는 UObject를 지운다
- **리플렉션**<br>런타임에 클래스 이름, 속성, 함수 목록을 알 수 있다.<br>에디터 노출, 블루프린트 연결, 직렬화, 네트워크 복제가 전부 이것 위에서 돈다
- **직렬화**<br>`UPROPERTY` 속성은 저장·불러오기와 에디터 편집이 자동으로 된다
- **CDO (Class Default Object)**<br>클래스마다 기본값을 가진 원본 객체가 하나 있다. 새 객체는 이것을 복사해서 만든다

**표시(매크로)와 UHT**
```cpp
UCLASS()                         // 이 클래스를 리플렉션에 등록
class AMyActor : public AActor
{
    GENERATED_BODY()             // UHT가 만든 코드가 들어오는 자리

    UPROPERTY(EditAnywhere)      // 이 속성을 리플렉션·GC·에디터에 등록
    int32 Health;

    UFUNCTION(BlueprintCallable) // 이 함수를 리플렉션·블루프린트에 등록
    void Heal(int32 Amount);
};
```
- C++에는 리플렉션이 없어서, 빌드 전에 **UHT(Unreal Header Tool)**가 헤더를 읽고 `*.generated.h`를 만든다.
- 서버로 치면 IDL을 읽어 직렬화 코드를 생성하는 코드 생성기(protoc)와 같다.

**접두사 규칙**

| 접두사 | 뜻 | 예 |
|---|---|---|
| `U` | UObject 계열 (액터 아님) | `UGameInstance`, `UActorComponent` |
| `A` | 액터 (세계에 놓이는 UObject) | `AActor`, `APawn` |
| `F` | 일반 C++ 구조체·클래스 (GC 없음) | `FVector`, `FString` |
| `E` | enum | `ECollisionChannel` |
| `I` | 인터페이스 | `IInteractable` |
| `T` | 템플릿 | `TArray`, `TMap` |
| `S` | Slate 위젯 (UI 하부 계층) | `SButton` |

**포인터와 메모리 (가장 먼저 걸리는 함정)**
- UObject를 가리키는 멤버는 `UPROPERTY()`를 붙이거나 `TObjectPtr<>`로 둔다.<br>그래야 GC가 "참조되고 있다"고 안다
- `UPROPERTY` 없는 raw 포인터(`UMyObject*`)로만 들고 있으면 GC가 조용히 지운다.<br>대부분 돌아가다가 특정 타이밍에만 죽는다
- 지워져도 괜찮은 참조는 `TWeakObjectPtr<>`
- UObject가 아닌 일반 C++ 객체는 `TSharedPtr` / `TUniquePtr` (표준 스마트 포인터와 같은 개념).<br>UObject와 섞지 않는다
- UObject는 `new`로 만들지 않는다.<br>`NewObject<T>()`(일반 UObject), `SpawnActor<T>()`(액터)로 만든다

# 3. 돌아가는 방식 - 메인 루프와 Tick

```
FEngineLoop::Tick()                      한 프레임
└─ UEngine::Tick()
   └─ UWorld::Tick()
      ├─ 입력 처리 (PlayerController)
      ├─ Tick 그룹 순서대로
      │   PrePhysics → 물리 → DuringPhysics → PostPhysics → PostUpdateWork
      │   각 그룹에서 Tick이 켜진 액터·컴포넌트의 Tick(DeltaTime) 호출
      ├─ 타이머 (FTimerManager)
      └─ 렌더링 스레드로 그릴 것을 넘김
```

- **가변 프레임이 기본이다.**<br>`Tick(float DeltaTime)`은 지난 프레임 이후 흐른 실제 시간(초)을 받는다.<br>서버의 고정 틱과 다르다
- **우리 프로젝트는 고정 틱을 코어에 둔다.**<br>UE의 Tick에서 쌓인 시간을 재서, 정해진 간격만큼 찼을 때 코어의 `Advance(N)`을 부른다.<br>"게임 루프 위에 고정 스텝 시뮬레이션을 얹는" 서버에서 흔한 방식과 같다
- **스레드**
  - **Game Thread**: 게임 로직과 Tick이 도는 곳. UObject는 기본적으로 여기서만 만진다
  - **Render Thread**, **RHI Thread**: 그리기. 게임 스레드가 넘긴 데이터를 가지고 따로 돈다
  - 무거운 작업은 Task Graph(작업 큐 / 스레드 풀)로 넘길 수 있다

# 4. 게임 프레임워크 - 누가 무엇을 맡나

언리얼은 멀티플레이를 기본에 깔고 설계돼 있어서, 역할이 서버·클라이언트 기준으로 나뉜다.

| 객체 | 맡는 것 | 어디에 있나 | 서버 비유 |
|---|---|---|---|
| `UGameInstance` | 게임 전체의 전역 상태, 맵 전환 사이에 살아남는 것 | 각 프로세스에 하나 | 애플리케이션 객체 |
| `UWorld` | 지금 맵의 모든 액터와 Tick | 맵마다 | 룸 / 존 |
| `AGameModeBase` | 게임 규칙, 입장 처리, 승패 판정 | **서버에만** | 권위 있는 룸 로직 |
| `AGameStateBase` | 모든 플레이어가 보는 게임 상태 | 서버 → 모든 클라 복제 | 브로드캐스트되는 공유 상태 |
| `APlayerController` | 한 플레이어의 입력과 의도 | 서버 + 그 플레이어 클라 | 연결(세션) 하나 |
| `APlayerState` | 플레이어별 공개 정보(점수 등) | 모두에게 복제 | 플레이어 프로필 |
| `APawn` / `ACharacter` | 플레이어나 AI가 조종하는 몸 | 세계 | 플레이어 엔티티 |
| `AHUD`, UMG 위젯 | 화면 UI | 각 클라 | 클라이언트 표시 계층 |

**Subsystem (현대 언리얼에서 권장하는 확장 지점)**
- 특정 객체의 수명에 맞춰 자동으로 생성·소멸되는 싱글턴 서비스.
- `UGameInstanceSubsystem`(게임 수명), `UWorldSubsystem`(맵 수명), `ULocalPlayerSubsystem`(로컬 플레이어 수명) 등.
- GameInstance를 상속해서 기능을 덕지덕지 붙이는 대신, 기능별로 서브시스템을 따로 만든다.<br>서버의 DI 컨테이너에 등록하는 서비스와 비슷하다.

**액터와 컴포넌트**
- 액터는 세계에 놓이는 "것"이고, 위치·회전은 루트 **SceneComponent**가 가진다.
- 메시 표시(`UStaticMeshComponent`), 충돌, 이동 같은 기능은 컴포넌트를 붙여서 조립한다.
- 상속보다 조합을 쓰는 구조다.

**블루프린트**
- C++ 클래스를 상속한 비주얼 스크립트.
- 보통 "C++로 뼈대와 무거운 로직, 블루프린트로 데이터와 조립"으로 나눈다.
- 블루프린트 클래스도 결국 UClass다.

# 5. Kingdom에서는 무엇을 쓰나 (예정)

우리 게임은 시뮬레이션을 순수 C++ 코어(KingdomCore)에 두고, 언리얼은 그리기·입력·UI만 맡는다.

```
UKingdomGameInstance
└─ (예정) UKingdomSimulationSubsystem : UGameInstanceSubsystem
   ├─ FSimulation 보유 (코어)                     맵이 바뀌어도 시뮬레이션이 산다
   ├─ 매 프레임 쌓인 시간 → 고정 틱 Advance(N)      배속·일시정지도 여기서
   └─ 세이브/로드: 코어가 준 바이트를 파일로

UWorld (지도 맵)
├─ (예정) 헥스 지도 액터                           코어 상태 → 텍스처 → 머티리얼로 그림
├─ (예정) APlayerController                        입력 → 커맨드 제출
└─ (예정) UMG 위젯                                 순위표, 영웅 목록, 알림
```

- **GameMode·GameState**: 싱글에서는 거의 쓰지 않는다. 규칙과 상태는 코어에 있기 때문이다.<br>온라인 전환 때 코어를 서버 쪽에 두는 구조로 다시 본다
- **액터를 헥스마다 만들지 않는다.**<br>수만 개의 액터는 Tick·메모리 비용이 커서, 지도는 텍스처 한 장으로 그린다 (기획서 11장 › 1차 › 필드)

# 6. 프로젝트와 빌드 (요약)

| 파일 | 하는 일 |
|---|---|
| `Kingdom.uproject` | 프로젝트 정의. 엔진 버전, 로드할 모듈 |
| `Source/*.Target.cs` | 무엇을 빌드할지(게임, 에디터, 서버) |
| `Source/<모듈>/<모듈>.Build.cs` | 모듈의 의존과 빌드 옵션(C#) |
| UBT (Unreal Build Tool) | 위를 읽어 컴파일러를 부르는 빌드 시스템 |
| UHT (Unreal Header Tool) | `UCLASS` 등을 읽어 리플렉션 코드 생성 |
| `Config/*.ini` | 엔진·게임 설정(기본 맵, GameInstance 클래스 등) |
| `Content/` | 에셋(.uasset, .umap). 바이너리라 Git LFS |

# 더 볼 것 (필요할 때 깊게)

- UObject 수명과 GC 상세 (언제 지워지나, `AddToRoot`, 레퍼런스 체인 디버깅)
- 리플렉션과 `UPROPERTY` 지정자 (`EditAnywhere`, `BlueprintReadWrite`, `Transient` …)
- Tick 그룹과 순서, 액터 Tick을 끄는 이유
- 서브시스템 수명과 초기화 순서
- 머티리얼과 텍스처로 데이터를 그리는 방법 (헥스 지도)
- UMG(UI)와 Slate
- `FArchive`와 `USaveGame` (언리얼의 직렬화와 세이브)
- 네트워크 복제 (온라인 전환 때)
