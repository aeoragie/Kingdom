# 서브시스템과 틱 - 엔진에서 우리 코드까지

> 4단계(배속·일시정지)에서 만든 `UKingdomSimulationSubsystem`과 `UKingdomGameInstance`가 엔진의 어디에서 만들어지고, 불리고, 지워지는지 따라간다.<br>줄 번호는 UE 5.8 엔진 소스 기준이다.<br>VS에서 함수 이름에 F12를 누르면 같은 곳으로 간다.

---

# 용어

**CDO (Class Default Object, 클래스 기본 객체)**<br>
UCLASS마다 엔진이 하나씩 만들어 두는 견본 객체다.<br>
멤버의 기본값을 담고 있고, 새 객체를 만들 때 이 값을 복사한다.<br>
에디터의 "기본값으로 되돌리기"도 이 객체와 비교한다.<br>
게임에 실제로 쓰이는 객체가 아니므로 틱하거나 시뮬레이션을 들면 안 된다.<br>
코드에서는 `IsTemplate()`(또는 `HasAnyFlags(RF_ClassDefaultObject)`)로 구별한다.

**Pacer (`FTickPacer`)**<br>
영어 pacer는 마라톤의 페이스메이커처럼 속도를 맞춰 주는 사람이다.<br>
`FTickPacer`는 실제로 흐른 시간을 받아 "이번에 몇 틱 돌릴지"를 정하는 코어 클래스다.<br>
배속, 일시정지, 의도치 않게 멈춰 있던 시간의 상한을 여기서 처리한다.

# 한눈에 보기

```
[1] 프로세스 시작
    모듈 DLL 로드 → UCLASS마다 UClass 등록 + CDO 생성

[2] 플레이(PIE) 시작
    에디터가 설정에서 GameInstance 클래스를 읽어 만든다 (UKingdomGameInstance)
      → UGameInstance::Init()
        → 서브시스템 모음이 UGameInstanceSubsystem 자식 클래스를 모두 찾아 만든다
          → UKingdomSimulationSubsystem::Initialize()   시뮬레이션 생성, 틱 켜기

[3] 매 프레임
    엔진 Tick → 월드 Tick → 틱 가능한 객체 목록 순회
      → UKingdomSimulationSubsystem::Tick(DeltaTime)
        → FTickPacer::Consume() → FSimulation::Advance(N)   (여기부터 코어)

[4] 콘솔 명령 (~ 키)
    콘솔 → 뷰포트 → GameInstance에서 UFUNCTION(Exec) 함수를 이름으로 찾음
      → UKingdomGameInstance::KingdomSpeed(8) → 서브시스템 SetSpeed(8)

[5] 플레이 종료
    UGameInstance::Shutdown() → 서브시스템 모음 정리
      → UKingdomSimulationSubsystem::Deinitialize()   틱 끄기, 시뮬레이션 삭제
      → 나중에 GC가 UObject를 지운다
```

---

# [1] 프로세스 시작 - 클래스가 엔진에 알려진다

- 에디터가 뜨면 `Kingdom.uproject`에 적힌 모듈(`KingdomGame`)의 DLL을 읽는다.
- `UCLASS()`를 붙인 클래스는 UHT가 만든 `.generated.h`·`.gen.cpp` 덕분에 DLL이 로드될 때 엔진에 등록된다.<br>
  엔진 안에 그 클래스의 설명서(`UClass`)가 생기고, CDO도 하나 만들어진다.
- 그래서 엔진은 우리 클래스를 코드에서 직접 부르지 않아도 "UGameInstanceSubsystem의 자식 클래스 목록"으로 찾아낼 수 있다.
- 서버로 치면 플러그인 DLL을 읽으면서 서비스 타입을 레지스트리에 등록하는 것과 같다.

**우리 코드에서 일어나는 일**
- `UKingdomSimulationSubsystem`의 CDO가 만들어진다.<br>
  이때 생성자가 불리고, `FTickableGameObject(ETickableTickType::Never)`로 틱 목록에서 빠진다.<br>
  CDO가 틱하지 않는 이유가 이것이다.

---

# [2] 플레이 시작 - GameInstance와 서브시스템이 만들어진다

**GameInstance는 설정이 정한다**
- `Config/DefaultEngine.ini`에 `GameInstanceClass=/Script/KingdomGame.KingdomGameInstance`가 있다.
- 플레이를 누르면 에디터가 이 값을 읽어 객체를 만든다.
  - `Editor/UnrealEd/Private/PlayLevel.cpp:2998`
    - `GetDefault<UGameMapsSettings>()->GameInstanceClass`
    - `NewObject<UGameInstance>(this, GameInstanceClass)`
  - 설정이 없으면 기본 `UGameInstance`가 만들어진다.
- 서버로 치면 설정 파일에 적힌 세션 클래스를 리플렉션으로 만드는 것이다.

**GameInstance가 서브시스템을 만든다**
- `Runtime/Engine/Private/GameInstance.cpp:279` `InitializeForPlayInEditor()`가 `Init()`을 부른다.
- `GameInstance.cpp:97` `UGameInstance::Init()` 안의 129번째 줄 `SubsystemCollection.Initialize(this)`.
- `Runtime/Engine/Private/Subsystems/SubsystemCollection.cpp:216` `FSubsystemCollectionBase::Initialize()`
  - `GetDerivedClasses(UGameInstanceSubsystem)`로 자식 클래스를 모두 찾는다
  - 클래스마다 CDO에 `ShouldCreateSubsystem()`을 물어보고, 만들어도 되면 `NewObject`로 만든다
  - 만든 객체의 `Initialize()`를 부른다
- 그래서 서브시스템은 어디에도 등록 코드를 쓰지 않는다.<br>
  클래스를 만들어 두기만 하면 엔진이 찾아서 만든다.
- 서버로 치면 DI 컨테이너가 인터페이스 구현체를 스캔해 세션 시작 때 만들어 주는 것과 같다.

**우리 코드에서 일어나는 일** (`KingdomSimulationSubsystem.cpp`)
- `Initialize()`
  - `Super::Initialize()`
  - `MakeUnique<Kingdom::FSimulation>(1)`로 코어 시뮬레이션을 만든다
  - `SetTickableTickType(GetTickableTickType())`로 틱을 켠다.<br>
    이제 CDO가 아니고 시뮬레이션도 있으므로 `Always`가 된다

# [3] 매 프레임 - Tick이 불린다

**엔진이 부르는 순서**
- 엔진 메인 루프가 매 프레임 `UEditorEngine::Tick()`(에디터) 또는 `UGameEngine::Tick()`(패키지된 게임)을 부른다.
- 그 안에서 월드를 틱하고, 틱 가능한 객체 목록을 돈다.
  - `Runtime/Engine/Private/Tickable.cpp:170` `FTickableGameObject::TickObjects(World, ...)`
  - 목록의 객체마다 "틱해도 되나", "이 월드 소속인가"를 보고 `Tick(DeltaSeconds)`를 부른다
- `TickObjects`는 두 곳에서 불린다.
  - 월드마다: `LevelTick.cpp:1821` `UWorld::Tick()` 안. 그 월드 소속 객체만 돈다
  - 월드 없이 한 번: 에디터 `EditorEngine.cpp:2219`, 게임 `GameEngine.cpp:1973`
- 서버로 치면 메인 루프의 프레임 업데이트가 등록된 핸들러를 차례로 부르는 것이다.

**우리 서브시스템은 "월드 없이" 쪽에서 불린다**
- `GetTickableGameObjectWorld()`를 덮어쓰지 않았으므로 소속 월드가 `nullptr`이다.
- 그래서 월드 없이 부르는 쪽(`EditorEngine.cpp:2219`)에서 틱한다.
- 이 호출은 일시정지 값을 항상 `false`로 넘긴다.<br>
  그래서 언리얼의 게임 일시정지(`SetGamePaused`)로는 우리 시뮬레이션이 멈추지 않는다.<br>
  우리는 `FTickPacer`의 일시정지를 따로 쓴다.

**우리 코드에서 일어나는 일**
- `Tick(DeltaTime)`
  - `DeltaTime`(초, float)을 정수 마이크로초로 바꾼다
  - `Pacer.Consume()`이 이번에 돌릴 틱 수를 정한다
  - 0보다 크면 `Simulation->Advance(N)`.<br>
    여기서부터는 UE를 모르는 코어다
  - `GEngine->AddOnScreenDebugMessage()`로 틱·배속·일시정지를 띄운다
- `GetStatId()`가 돌려주는 이름표로 `stat` 명령이나 Unreal Insights에서 이 Tick의 비용을 볼 수 있다.

# [4] 콘솔 명령 - UFUNCTION(Exec)

- `~` 키로 연 콘솔에 `KingdomSpeed 8`을 치면, 엔진이 명령을 받아 줄 객체를 차례로 찾는다.
  - 대상: 플레이어 컨트롤러, 치트 매니저, 게임 모드, GameInstance 등
- `Runtime/Engine/Private/GameViewportClient.cpp:3524`에서 GameInstance 차례가 온다.
  - `GameInstance->Exec(...)`
  - `GameInstance->ProcessConsoleExec(...)`
- `ProcessConsoleExec`는 리플렉션으로 그 객체의 `UFUNCTION(Exec)` 함수 중 이름이 맞는 것을 찾는다.<br>
  뒤의 `8`은 함수 인자로 변환해 넘긴다.
- 서브시스템은 이 대상 목록에 없다.<br>
  그래서 GameInstance에 명령을 두고 `GetSubsystem<UKingdomSimulationSubsystem>()`으로 넘긴다.
- 서버로 치면 운영 툴의 관리자 명령을 이름으로 디스패치하는 것과 같다.

---

# [5] 플레이 종료 - 지워지는 순서

- 플레이를 멈추면 `GameInstance.cpp:147` `UGameInstance::Shutdown()`이 불린다.
- 167번째 줄 `SubsystemCollection.Deinitialize()`가 서브시스템마다 `Deinitialize()`를 부른다.
- 그 뒤 GameInstance와 서브시스템은 참조가 끊기고, 다음 GC 때 지워진다.

**우리 코드에서 일어나는 일**
- `Deinitialize()`
  - `SetTickableTickType(Never)`로 틱부터 끈다.<br>
    반쯤 정리된 상태에서 Tick이 불리지 않게 하려는 것이다
  - `Simulation.Reset()`으로 코어 시뮬레이션을 지운다
  - `Super::Deinitialize()`
- 다시 플레이하면 [2]부터 다시 일어나므로 틱은 0부터 시작한다.

# 우리 코드와 엔진의 연결 정리

| 우리 코드 | 엔진의 무엇에 붙나 | 누가 부르나 |
|---|---|---|
| `UKingdomGameInstance` | `UGameInstance` 상속 | `DefaultEngine.ini`의 `GameInstanceClass`를 보고 에디터·게임 엔진이 만든다 |
| `KingdomSpeed`, `KingdomPause` | `UFUNCTION(Exec)` | 콘솔 → 뷰포트 → `GameInstance->ProcessConsoleExec` |
| `UKingdomSimulationSubsystem` | `UGameInstanceSubsystem` 상속 | `UGameInstance::Init()` → 서브시스템 모음이 자식 클래스를 찾아 만든다 |
| `Initialize`, `Deinitialize` | `USubsystem`의 가상 함수 | 서브시스템 모음 (GameInstance 시작·종료 때) |
| `Tick`, `GetStatId`, `GetTickableTickType` | `FTickableGameObject` 상속 | 매 프레임 `FTickableGameObject::TickObjects` |
| 생성자의 `FTickableGameObject(Never)` | 틱 목록 등록 규칙 | CDO가 만들어질 때 틱하지 않게 |
| `TUniquePtr<FSimulation>`, `FTickPacer` | 엔진과 무관한 일반 C++ | 서브시스템이 직접 소유한다(GC 대상 아님) |
